# LoongArch 架构下 SPDK 高性能存储栈技术调研与实践总结

## 一、 核心架构概述：SPDK 与 DPDK 的协同
在高性能存储领域，SPDK (Storage Performance Development Kit) 与 DPDK (Data Plane Development Kit) 是相辅相成的层级关系。

*   **DPDK (地基层)**：负责**环境抽象 (EAL)**。它通过 **轮询 (PMD)**、**大页内存 (Hugepages)** 和 **UIO/VFIO** 技术，将 CPU、内存和 PCIe 总线的控制权从内核手中“抢”到用户态，消除了中断和上下文切换的开销。
*   **SPDK (引擎层)**：运行在 DPDK 之上。它利用 DPDK 提供的无锁队列和内存池，实现了**用户态 NVMe 驱动**、**块设备抽象层 (Bdev)** 和 **存储协议栈 (NVMe-oF)**。

---

## 二、 LoongArch64 架构适配要点
在龙芯 3C6000 平台上，实现 Kernel Bypass 的关键适配工作包括：

1.  **内存模型适配**：LoongArch 属于弱内存模型，必须在 DPDK/SPDK 的无锁环形缓冲区中正确嵌入 **`dbar`** 指令，以防止 CPU 指令重排导致的数据损坏。
2.  **原子操作**：利用龙芯的 LL/SC 或 AM 指令集实现高效的原子加减与比较交换，这是多核并发的基础。
3.  **向量化加速 (SIMD)**：针对 **ISA-L** 算法库（纠删码、CRC、压缩），需将 x86 的 AVX 指令映射为龙芯的 **LASX (256位)** 或 **LSX (128位)** 向量指令，以实现性能质变。

## 三、 工程实践步骤：从源码到运行

### 1. 环境准备与发行版适配
由于 OpenCloudOS 9.4 暂不在 SPDK 官方支持列表中，我们通过以下手段完成了环境构建：
*   **发行版映射**：修改 `pkgdep.sh` 将 OpenCloudOS 映射为 `rhel` 模式。
*   **依赖清理**：移除龙芯架构下暂不支持的第三方仓库（如 Ceph, ELRepo），改用本地 `EPOL` 源安装核心工具（Clang 17, Meson, Ninja）。

### 2. 编译策略优化
*   **模块精简**：因 `CUnit` 依赖缺失，通过禁用 `ut` (单元测试) 目录并配置 `--disable-unit-tests` 保证主程序构建。
*   **并发控制**：在龙芯 64 核环境下，将编译并发度调整为 `-j8`，以规避高并发下的临时文件竞争报错。

### 3. 功能验证方案
*   **Malloc Bdev (内存块设备)**：在用户态开辟内存空间模拟物理硬盘。这验证了 **DPDK 大页内存管理** 和 **SPDK 逻辑卷管理** 在龙芯上的正确性。
*   **NBD (网络块设备) 映射**：
    *   **原理**：通过 NBD 驱动在内核 `/dev/` 下创建虚拟设备，并通过 Socket 与用户态 SPDK 通信。
    *   **目的**：建立用户态存储与内核文件系统的桥梁，允许使用 `mkfs.ext4` 和 `mount` 进行标准读写测试，确认数据平面通路已打通。

## 四、 高性能网络方案对比：TCP vs. RDMA

在龙芯服务器之间实现物理验证环境时，网络后端的选择决定了 Bypass 的深度：

| 技术方案 | TCP (POSIX) | TCP (用户态协议栈) | **RDMA (RoCE/iWARP)** |
| :--- | :--- | :--- | :--- |
| **协议栈位置** | **内核** (Kernel Space) | **用户态软件** (VPP/msquic) | **网卡硬件** (ASIC) |
| **CPU 消耗** | 较高 (处理 TCP 逻辑) | 中 (轮询处理协议栈) | **极低 (接近 0)** |
| **数据拷贝** | 存在内核/用户态拷贝 | 零拷贝 (依赖实现) | **完全零拷贝** |
| **适配难度** | 低 (直接使用 Socket) | 高 (需适配龙芯向量指令) | 中 (需支持 RDMA 的网卡) |
| **当前现状** | **当前已跑通**，性能受限 | 调研中，开发成本高 | **推荐方案**，硬件卸载协议栈 |

## 六、 SPDK NVMe-oF (NVMe over Fabrics) 深度架构分析

NVMe-oF 是 SPDK 的核心组件，旨在将本地 NVMe 的极致性能通过网络延伸至远程客户端。其架构实现了从网络到磁盘的端到端 **Kernel Bypass** 与 **零拷贝**。

### 1. 分层架构设计
SPDK 的 NVMe-oF 实现采用了高度模块化的三层架构：

*   **前端：传输层 (Transport Layer)**
    *   **抽象接口**：定义了统一的 Transport 接口，屏蔽底层物理媒介差异。
    *   **RDMA 后端**：通过 `libibverbs` 直接驱动 HCA 硬件（如 Mellanox），调用 `ibv_post_send` 实现硬件级协议解析，延迟最低。
    *   **TCP 后端**：利用 POSIX Socket 或用户态 TCP 协议栈（如 msquic），在普通以太网（如 Intel XL710）上实现高兼容性存储导出。
*   **中枢：控制器逻辑 (Controller Logic)**
    *   **协议解析**：在用户态解析封装在 Fabric 报文中的 NVMe 指令（Read/Write/Admin）。
    *   **状态机管理**：维护 NVMe 提交队列 (SQ) 与完成队列 (CQ)，模拟标准 NVMe 控制器行为。
*   **后端：Bdev 抽象层 (Block Device Layer)**
    *   将解析后的 I/O 请求下发至具体的存储后端。支持物理 **NVMe SSD**（通过用户态驱动）、**Malloc 虚拟盘**或 **Lvol 逻辑卷**。

### 2. 核心性能基石
*   **Shared-Nothing 线程模型**：每个 CPU 核心（Reactor）独立管理一组网络连接与磁盘队列，核心间无锁竞争，极大提升了多核龙芯（如 3C6000）的并行处理能力。
*   **异步轮询 (Async Polling)**：通过 DPDK 的 PMD 驱动持续轮询网卡与 SSD 状态，消除内核中断上下文切换开销。
*   **零拷贝映射**：利用 DPDK 大页内存池，数据从网卡进入到下发 SSD 过程中不产生 CPU 内存拷贝。

### 3. LoongArch 架构适配优势
*   **规避内核系统调用开销**：在处理大规模并发 I/O 时，避开了传统 Linux 内核栈的性能瓶颈，充分释放龙芯多核算力。
*   **指令集优化潜力**：NVMe-oF 协议涉及密集的 CRC 校验与数据封包。通过适配龙芯 **LASX (256位)** 向量指令，可显著提升协议解析与数据完整性校验的效率。
*   **自主可控存储基石**：作为构建龙芯全闪存阵列（All-Flash Array）的核心技术，NVMe-oF 为实现高性能、低延迟的存算分离架构奠定了技术基础。
